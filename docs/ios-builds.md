# iOS builds and app icons

The existing mobile workspace now targets Android and iOS. Android retains payment notification capture. The iOS app opens the hosted creator dashboard in the system browser for Google sign-in, stream setup and alert management. It does not capture other apps' payment notifications or pair as a capture device.

## Build from Windows with EAS

Run from the repository root:

```powershell
npm run ios:configure
npm run ios:build:simulator
npm run ios:build:preview
npm run ios:build:release
```

The configure command requires an Expo account and links this workspace to your EAS project. Before building, set `EXPO_PUBLIC_WEB_URL` to your deployed HTTPS web origin in the EAS environment used by each profile (preview for simulator/preview; production for release). This is a public URL, not a secret. Without it, the app displays a configuration error when opening the dashboard.

Simulator builds produce an unsigned simulator `.app` archive; preview produces a signed device `.ipa` for registered devices; release produces a signed App Store `.ipa`. EAS provides artifact download links after the remote build. Device builds require Apple Developer membership and signing credentials. Installing simulator artifacts or running `npm run dev:ios` locally requires macOS and Xcode. An IPA cannot be compiled locally on Windows. These scripts do not submit anything to the App Store.

EAS CLI is invoked through npm exec on first use. Native iOS sources are generated by Expo prebuild on the remote macOS builder. Do not run prebuild for Android: that project contains custom Kotlin code.

## Icons

`packages/frontend/tiprelay-android/assets/icon.png` is the opaque 1024px TipRelay arrow icon used by Expo for iOS. The matching Android density assets are checked into `android/app/src/main/res/mipmap-*`. Native icons require rebuilding the app; Metro refresh does not update an installed launcher icon.

The iOS binary has not been built or device-tested in this Windows workspace. This initial iOS dashboard launcher does not provide native feature parity and needs device validation and App Store review before release.
